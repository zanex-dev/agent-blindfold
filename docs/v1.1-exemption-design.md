# `agent-blindfold` (Heart-Under-Blade / 刃下心) v1.1 架构升级蓝图

> **核心目标**：在不削弱任何个人隐私目录（`Pictures` / `Videos` / `Music` / `AppData` 及裸 `Desktop` / `Downloads` / `Documents`）零信任物理隔离的前提下，彻底打通**工程沙盒自动豁免**与**会话开局下发豁免（支持限时 TTL / 永久 Permanent 双模式）**，并封堵 Agent 自行伪造 `.allow_media` 的提权越狱漏洞。

---

## 1. 痛点复盘与安全边界

1. **前端/UI 工程“蒙眼盲写”问题**：
   - 当用户在 Antigravity 未挂载显式工作区（`workspacePaths` 为空）直接开发前端项目时，项目位于 `~/.gemini/antigravity/scratch/<project>`，产物位于 `artifactDirectoryPath`（`~/.gemini/antigravity/brain/<conversationId>`），Playwright 视觉验收截图位于 `.playwright-mcp/`。v1.0.0 将上述路径全部误判为“外部私人目录”拦截，导致 Agent 无法对自己刚生成的 UI 画面做截图视觉验收。
2. **工作区豁免缺失“开局自动下发”与“限时 TTL vs 永久”生命周期**：
   - v1.0.0 的 `.allow_media` 仅支持手动创建空文件，既不会在开工时自动下发，又缺乏过期销毁机制（一旦忘记手动删除即沦为永久裸奔）。
3. **Agent 自签发越狱漏洞（Privilege Escalation）**：
   - v1.0.0 未拦截 `write_file` / `edit_file` / `Write` / `Edit` 及终端 `touch .allow_media`，导致 Agent 看到报错提示后可自行创建 `.allow_media` 绕过防线。

---

## 2. 四级零信任与工程豁免架构（v1.1）

### Tier 0：工程代码与 Agent 自产沙盒自动豁免（Auto-Exempted Engineering Sandboxes）
在完成符号链接与目录联接（Symlink / Junction）真实路径解析后（确保无法通过软链指向个人禁区逃逸）：
1. **矢量工程代码 `.svg`**：只要真实路径不在 Tier 1 私人禁区及非项目根级的个人容器目录内，一律视为纯文本前端代码自动放行。
2. **当前会话专属产物目录（`artifactDirectoryPath` / `brain/<conversationId>`）**：
   - 自动放行当前会话目录下的工程构建产物与渲染截图；
   - **跨会话上传隔离**：若路径包含 `.user_uploaded`，仅当属于**当前 `conversationId`** 时允许访问，严禁跨会话读取历史对话的用户上传媒体。
3. **Antigravity 官方工程草稿沙盒（`~/.gemini/<antigravity|antigravity-cli|antigravity-ide>/scratch/<subproject>`）**：
   - 自动将 `scratch/<subproject>`（必须为具体子项目目录，而非 `scratch` 根目录本身）识别为受信任的独立工程沙盒并自动放行工程产物。
4. **前端自动化测试临时截图目录（`.playwright-mcp`）**：
   - 位于合法独立项目工作区或 `scratch`/`brain` 沙盒内的 `.playwright-mcp/` 视觉回归截图自动放行，保障前端任务视觉闭环。

### Tier 1：核心私人禁区（Hard Personal Vaults — 永久物理焊死）
- `Pictures`、`Videos`、`Music`、`AppData`（任意层级），以及直接访问或直接作为根工作区打开的 `Desktop`、`Downloads`、`Documents`。
- **无条件 `deny`**，`SessionStart` 绝不下发通行证，手工放置 `.allow_media` 亦无效。

### Tier 2：外部非工程目录（External Directories — 无条件物理隔离）
- 不属于 Tier 0 工程沙盒，也不属于当前合法独立项目工作区（`workspacePaths` / `cwd`）的任何本地路径。
- **无条件 `deny`**。

### Tier 3：独立项目工作区（Dedicated Project Workspace — 支持开局下发 + 限时/永久双模通行证）
- 支持通过 `SessionStart` 开局自动下发或通过 `unlock.ps1` / `unlock.sh` 一键下发 `.allow_media` 通行证：
  - **限时模式（`timed`，默认推荐）**：JSON 格式 `{"version":1,"mode":"timed","ttl_seconds":7200,"issued_at":...,"expires_at":...,"issued_by":"..."}`（亦兼容纯文本时长如 `2h` / `30m`，或旧版空文件默认按文件 `mtime + 默认 TTL 2h` 计算过期）。到期后 `guard` 自动判定失效并清理过期文件。
  - **永久模式（`permanent`）**：JSON 格式 `{"version":1,"mode":"permanent","issued_at":...,"issued_by":"..."}`（亦兼容纯文本 `permanent`）。长期生效直至用户主动执行 `lock`。

## 3. 开局豁免下发机制（`SessionStart` + 用户控制工具）

1. **全局策略配置 `~/.gemini/config/agent-blindfold.json`**（跨平台统一路径，可通过 `unlock.ps1` / `unlock.sh` 或 `install` 参数配置）：
   ```json
   {
     "sessionAutoGrant": "timed",
     "defaultTTL": "2h"
   }
   ```
   - `sessionAutoGrant` 可选值：
     - `"timed"`（默认）：每次会话启动（`SessionStart`）时，若当前挂载了合法的 Tier 3 独立项目工作区（且当前无有效的 `permanent` 通行证），自动签发一张时长为 `defaultTTL`（默认 `2h` = 7200 秒）的限时 `.allow_media` 通行证，并在 Antigravity 中通过 `injectSteps` 注入系统状态说明。
     - `"permanent"`：每次会话启动时，对合法独立项目工作区自动签发永久通行证。
     - `"off"`（或 `"sandbox_only"`）：开局不在普通业务仓库自动写 `.allow_media`（Tier 0 工程沙盒依然自动豁免），仅在用户手动执行解锁脚本时签发。
2. **跨平台通行证管理与开局切换器（`scripts/unlock.ps1` & `scripts/unlock.sh`）**：
   - 支持命令行直接控制与交互式菜单：
     - 签发限时豁免：`unlock.ps1 -Mode timed -TTL 2h [-Workspace <dir>]`
     - 签发永久豁免：`unlock.ps1 -Mode permanent [-Workspace <dir>]`
     - 立即收回锁死：`unlock.ps1 -Lock [-Workspace <dir>]`
     - 查看当前状态与剩余时间：`unlock.ps1 -Status [-Workspace <dir>]`
     - 设置全局开局默认策略：`unlock.ps1 -GlobalAutoGrant timed|permanent|off [-TTL 2h]`（兼容别名 `-SetGlobalAutoGrant`）
   - 在 Windows 本地环境同步提供一键双击穿透启动器（`blindfold-control.cmd`），支持用户在真实桌面随时可视化切换“限时豁免 / 永久豁免 / 立即锁死 / 开局策略”。

## 4. 防提权篡改守卫（Anti-Tamper Guard）

- 在 `PreToolUse` 中扩展拦截范围至所有文件写入与编辑工具（`write_file`, `write_to_file`, `edit_file`, `replace_file_content`, `multi_replace_file_content`, `Write`, `Edit`, `MultiEdit`, `call_mcp_tool`）以及终端命令（`run_command`, `Bash`）。
- 任何工具调用一旦试图创建、写入、修改、删除 `.allow_media`、`agent-blindfold.json` 或在终端调用 `unlock.ps1` / `unlock.sh`（允许安全的纯只读 `git status` / `git diff`），立即返回 `HARD DENY`（双语警告：严禁 Agent 自行签发或篡改媒体豁免通行证）。
- 由于宿主 `SessionStart` 钩子由宿主直接调用、不经过 Agent `PreToolUse`，天然实现了**“宿主开局与人类用户可签发、AI 智能体不可自签发”**的零信任权限隔离。
